<task type="auto">

  <read_first>backend/faers/downloader.py, backend/faers/registry.py</read_first>
  <action>
1. Producer: once a day, check for a FAERS quarter newer than the registry's latest and publish `faers-release` with the quarter name.
2. `faers/pipeline.py`: `refresh(quarter)` runs download, parse, load, identity build, then recomputes the watchlist signals under the new data version.
3. Consumer: on `faers-release`, record "new quarter available". Run `refresh` automatically only when `FAERS_AUTO_REFRESH` is on; otherwise an admin starts it. Either way it runs as a job, never inline in the consumer loop.
4. The dashboard shows a notice when a newer quarter is available.
  </action>
  <verify>venv\Scripts\python.exe -m pytest backend/tests/test_ingest.py -k release -q</verify>
  <acceptance_criteria>
    - A `faers-release` message for an already-loaded quarter does nothing.
    - With auto-refresh off, the message creates a notice and no download.
  </acceptance_criteria>
  <done>Kafka drives the data refresh.</done>
</task>
