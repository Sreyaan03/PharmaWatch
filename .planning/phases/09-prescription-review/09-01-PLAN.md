  <action>
1. Table `jobs(id, kind, status, input_ref, result_json, error, created_by, created_at, expires_at)`.
2. `core/jobs.py`: create, claim, complete, fail, fetch, purge-expired; a small worker pool inside the app process. The interface is the only thing callers use, so a real queue can replace it later.
3. Files go to `DATA_DIR/uploads/<job id>` and are deleted when the job finishes or expires.
4. Move the NER mining flow from the in-memory `MINING_TASKS` dict to jobs, keeping its endpoints and its progress stream.
5. Enforce the existing 10 MB and file-type limits before anything is stored.
  </action>

  <acceptance_criteria>

    - `MINING_TASKS` no longer exists.
  </acceptance_criteria>
  <done>Background work has durable, bounded state.</done>
</task>

<task type="auto">
  <name>Task 2: Extraction schema and cloud vision client</name>
  <files>backend/clients/vision.py, backend/services/prescription/schema.py, backend/requirements.txt, backend/core/config.py</files>
  <read_first>backend/clients/http.py, backend/core/config.py</read_first>
  <action>
1. `schema.py`: one medication line is `drug_text, strength, dose_form, dose, route, frequency, duration, as_needed, confidence, notes`; the result also carries `unreadable_regions` and `extractor`.
2. `clients/vision.py`: send the page images to the Claude API and require output matching the schema. Model from `RX_VISION_MODEL` (default `claude-opus-5-5`), key from `ANTHROPIC_API_KEY`. Follow the current Anthropic SDK guidance for image input and structured output when implementing.
3. Instruct the model to transcribe medication lines only, to leave fields empty when unreadable instead of guessing, and to omit patient and prescriber identifiers.
4. Timeouts, one retry, and a typed error on failure. Log job id and line count only, never content.
  </action>
  <verify>venv\Scripts\python.exe -m pytest backend/tests/test_prescription_extract.py -k vision -q</verify>
  <acceptance_criteria>
    - With the API mocked, a response parses into the schema and a malformed response raises the typed error.
    - No test makes a real API call.
  </acceptance_criteria>
  <done>Cloud extraction returns structured, schema-checked lines.</done>
</task>

<task type="auto">

  <files>backend/services/prescription/extract.py, backend/tests/test_prescription_extract.py</files>

  <action>
1. `Extractor` protocol with `extract(file_bytes, mime) -> ExtractionResult`.
2. `CloudVisionExtractor` uses the client above. `LocalOcrExtractor` reuses the existing PDF rasterising, EasyOCR and NER code, plus a small parser for strength and frequency abbreviations; it marks its lower confidence.
3. `get_extractor()` picks cloud when a key is configured, local otherwise, and the result always names which one ran so the UI can disclose it.
4. Rasterise PDFs once, at a resolution suited to each extractor.
  </action>
