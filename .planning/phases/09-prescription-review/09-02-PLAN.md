<task type="auto">
  <name>Task 1: Endpoints and the confirmation gate</name>
  <files>backend/routes/prescription.py, backend/app.py, backend/tests/test_prescription_review.py, backend/tests/fixtures/route_inventory.json</files>
  <read_first>backend/routes/signals.py, backend/core/jobs.py</read_first>
  <action>
1. `POST /api/prescription` (upload, returns job id); `GET /api/prescription/<id>` (status and extracted lines); `POST /api/prescription/<id>/confirm` (the corrected list); `GET /api/prescription/<id>/report` and `.../report.pdf`.
2. Each extracted line is resolved through the identity service before it is shown, so the user sees the matched ingredient or "not recognised" next to the transcribed text.
3. The report endpoints return 409 until a confirmed list exists. The confirmed list, not the extraction, is the report's input, and both are kept so accuracy can be measured.
4. Lines the user leaves unresolved are listed in the report as not analysed.
  </action>
  <verify>venv\Scripts\python.exe -m pytest backend/tests/test_prescription_review.py -k gate -q</verify>
  <acceptance_criteria>
    - Requesting a report before confirmation returns 409.
    - Extraction and confirmation are stored separately.
  </acceptance_criteria>
  <done>A human confirms every medication list.</done>
</task>

<task type="auto">
  <name>Task 2: Review service</name>
  <files>backend/services/prescription/review.py, backend/services/interactions.py, backend/tests/test_prescription_review.py</files>
  <read_first>backend/services/interactions.py, backend/services/boxed_warnings.py, backend/services/signals.py</read_first>
  <action>
1. Pairwise interactions: call the existing polypharmacy evaluation. Lift its five-drug limit to a configured maximum with a cap on pair count, and evaluate pairs in the existing thread pool.
2. Per drug: boxed warning (existing lookup), most reported reactions (existing FAERS query), current signals whose class is not `none`.
3. Duplicate therapy: two lines with the same ingredient, or the same pharmacological class from the label data the boxed-warning lookup already retrieves.
4. Order findings: documented interactions, boxed warnings, duplicate therapy, model-predicted interactions, signals. Each finding carries its evidence type and source snippet.
5. Summary text is assembled from the structured findings by fixed templates, so it cannot state anything the findings do not contain.
6. Dose checking is out of scope and the report says so.
  </action>
  <verify>venv\Scripts\python.exe -m pytest backend/tests/test_prescription_review.py -k review -q</verify>
  <acceptance_criteria>
    - With services mocked, a three-drug list yields three pair results and per-drug sections.
    - Two lines of the same ingredient produce a duplicate-therapy finding.
    - The words "safe" and "safe to combine" never appear.
  </acceptance_criteria>
  <done>The review is a composition of tested services.</done>
</task>
