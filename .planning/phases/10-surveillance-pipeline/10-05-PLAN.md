<task type="auto">
  <name>Task 4: Lead-time study</name>
  <files>backend/validation/lead_time.py, backend/validation/report.py, backend/tests/test_lead_time.py, reports/validation/lead_time.json</files>
  <action>
1. For each label change, find the first quarter in which the pair was a signal (cumulative from 2021Q3) and compare it with the quarter of the label change.
2. Report four groups separately, never merged:
   - flagged before the change, with lead time in quarters;
   - flagged at or after the change;
   - already a signal in 2021Q3 (left-censored: our data starts there, so the true first flag is unknown);
   - never flagged.
3. Give the share flagged before the change with a bootstrap CI, and the median lead time with its CI.
4. State these caveats on the page:
   - Only 20 quarters are loaded.
   - Reporting rises after label changes (stimulated reporting).
   - FAERS dates are receipt dates.
   - Label changes are not a complete list of true adverse effects.
5. Wire into `run_all`, the summary and the Methods page. Unit tests cover each group and the censoring rule on a fixture.
  </action>
  <verify>venv\Scripts\python.exe -m pytest backend/tests/test_lead_time.py -q && venv\Scripts\python.exe -m validation.lead_time</verify>
  <acceptance_criteria>
    - The result is published even if FAERS mostly flagged effects after the label changed.
    - Left-censored pairs never count as "flagged before".
  </acceptance_criteria>
  <done>The system's early-warning value is measured, not claimed.</done>
</task>
