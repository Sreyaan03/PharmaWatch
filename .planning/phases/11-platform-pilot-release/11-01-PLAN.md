<task type="auto">
  <name>Task 1: Accounts and roles</name>
  <files>backend/core/auth.py, backend/core/manage.py, backend/routes/auth.py, backend/app.py, backend/db/schema.sql, backend/db/migrate.py, backend/tests/test_auth.py, src/index.html, src/auth.js, src/api_layer.js</files>
  <read_first>backend/core/auth.py, backend/app.py</read_first>
  <action>
1. Table `users(id, email, password_hash, role, organisation, active, created_at)`. Hash with Werkzeug, which Flask already installs.
2. Signed, HTTP-only session cookie using `FLASK_SECRET_KEY`; the app refuses to start in production mode without one.
3. `AuthProvider` interface with a local-accounts implementation, so single sign-on can be added later without touching routes.
4. Decorators `require_login` and `require_role`. Viewer: read results. Analyst: run analyses, upload, give feedback. Admin: users, training, data refresh, exports.
5. `python -m core.manage create-user` and `set-role`; no self-registration.
6. Login view and sign-out in the frontend; `ApiLayer` redirects to login on 401.
7. `AUTH_REQUIRED=false` keeps single-user local development simple and is shown as a banner when off.
  </action>
  <verify>venv\Scripts\python.exe -m pytest backend/tests/test_auth.py -q</verify>
  <acceptance_criteria>
    - A viewer cannot upload or train; an analyst cannot manage users.
    - Passwords are never stored or logged in clear text.
  </acceptance_criteria>
  <done>Access is controlled by role.</done>
</task>

<task type="auto">
  <name>Task 2: Audit log</name>
  <files>backend/core/audit.py, backend/app.py, backend/db/schema.sql, backend/db/migrate.py, backend/tests/test_audit.py</files>
  <read_first>backend/core/response.py</read_first>
  <action>
1. Table `audit_log(id, at, user_id, action, route, inputs_json, data_version, model_version, status, request_id)`.
2. An after-request hook writes one row for every analysis, upload, confirmation, export, login and admin action. Inputs are the drug and event identities and parameters; document content and free text are never recorded.
3. The application's database user gets insert and select only on this table; the code exposes no update or delete.
4. Admin endpoint to page and export the log.
  </action>
  <verify>venv\Scripts\python.exe -m pytest backend/tests/test_audit.py -q</verify>
  <acceptance_criteria>
    - Running a signal query writes one row with both versions.
    - A prescription upload writes a row with no document content.
  </acceptance_criteria>
  <done>Every result can be traced to a user, data version and model version.</done>
</task>
