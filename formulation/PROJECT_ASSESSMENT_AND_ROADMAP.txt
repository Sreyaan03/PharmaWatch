The Good:
The domain depth, algorithmic rigor, and architectural ambition of this project
are extraordinary for an individual/small team. This is NOT a trivial mock UI:
- Real disproportionality statistics (Haldane-corrected PRR, ROR, EBGM, IC)
- Real analytical querying on FAERS parquet data via DuckDB
- Real Apache Kafka event-driven pub/sub streaming pipeline

The Reality:
The project currently suffers from "Feature Sprawl without Architectural Decoupling."
It attempts to run an enterprise-scale distributed big-data and deep-learning stack
(Kafka + ZooKeeper + HBase + DuckDB + SQLite + PyTorch + Transformers + Flask)
on a single local machine without automated tests, unified container orchestration,
or decoupled state management.

2. WHAT MAKES THE PROJECT STRONG (CORE ASSETS)
--------------------------------------------------------------------------------
1. True Pharmacovigilance Rigor:
   Implements valid epidemiological formulas, statistical shrinkage, and zero-cell
   Haldane corrections matching FDA/WHO standards rather than trivial counts.

2. Multi-Model Machine Learning:
   Combines three distinct ML paradigms:
   - Graph Neural Networks (GNN) for molecular polypharmacy DDI prediction
   - Recurrent Neural Networks (LSTM) for adverse event temporal trajectory forecasting
   - Transformer NLP (BioBERT) for clinical unstructured text entity recognition

3. Real-Time Streaming Backbone:
   A functional Apache Kafka broker with live producer polling FDA RSS and openFDA
   recalls, and consumer engines computing risk scores and persisting alerts.

4. High Visual Engagement:
   Glassmorphic dark design, responsive Chart.js visualizers, and interactive
   3D molecular and drug interaction graphs.

--------------------------------------------------------------------------------
3. THE 5 MAJOR THINGS HOLDING IT BACK
--------------------------------------------------------------------------------
1. Monolithic Frontend & Fragile State Management:
   - src/index.html is ~97 KB of raw HTML in a single file.
   - src/app.js is ~105 KB accompanied by scattered auxiliary scripts
     (_interactions_new.js, distributed_storage.js, guide.js).
   - Heavy reliance on global variables (window.*), direct DOM manipulation, and
     manual HTML string concatenation.
   - Input handlers without robust state guards caused bugs (e.g., typing
     "Clotrimazole" prematurely queried "Cl" chlorine SMILES mid-word).

2. Zero Automated Test Coverage (0% Test Suite):
   - There is NO tests/ directory in the entire codebase.
   - Zero unit tests, zero API contract tests, zero model regression tests.
   - Every modification requires starting 5 terminals and manually clicking
     through the UI to see if something broke.

3. Distributed Infrastructure Friction on Local Machines:
   - HBase runs as an orphaned, unmanaged container (hbase-server) outside of
     docker-compose.yml.
   - HBase holds ports 2181, 8080, and 8085, forcing Kafka ZooKeeper to 2182 and
     Kafka-UI to 8086.
   - Running `docker compose up --build` takes 20-30+ minutes because CPU PyTorch,
     transformers, and dependencies build from scratch.

4. Synchronous ML Inference & Database Concurrency Bottlenecks:
   - BioBERT and GNN models run synchronously on CPU inside the Flask request
     thread, blocking concurrent requests.
   - The Kafka consumer writes incoming streaming alerts to backend/pharmawatch.db
     while Flask reads from it. SQLite under continuous write load risks
     "sqlite3.OperationalError: database is locked".

5. Repository Data Bloat & Fragile Dependencies:
   - Huge static datasets on disk: twosides.csv (677 MB), drugbank_ddi.tsv (44 MB),
     pharmawatch_faers.duckdb (25 MB).
   - backend/requirements.txt had omitted dependencies (thrift, feedparser) and
     an outdated kafka-python pin that breaks on newer Python environments.

--------------------------------------------------------------------------------
4. WHAT TO AVOID (THE OVER-ENGINEERING TRAPS)
--------------------------------------------------------------------------------
Do NOT make these well-intentioned but dangerous mistakes right now:

[TRAP 1] Rewriting the Frontend in React / Vue / Next.js:
- WHY TO AVOID: Rewriting ~150 KB of working Vanilla JS, 3D Canvas graphs,
  Chart.js visualizers, and custom glassmorphism into React will consume 2-3
  weeks of development time, break dozens of subtle DOM event listeners, and
  provide zero new capability to users.
- BETTER PATH: Keep the vanilla stack, but modularize functions, clean up global
  variables, and add defensive input validation guards.

[TRAP 2] Adding Celery + Redis for Asynchronous ML Workers:
- WHY TO AVOID: Your machine already runs ZooKeeper, Kafka Broker, Kafka UI,
  HBase, Kafka Producer, Kafka Consumer, and Flask. Adding Redis and Celery daemon
  processes means managing 8+ concurrent services.
- BETTER PATH: Use Python's built-in `concurrent.futures.ThreadPoolExecutor`
  inside Flask for non-blocking operations. Zero extra containers, zero extra RAM.

5. CRITICAL ADDITIONS THAT WERE MISSING (HIGH-IMPACT WINS)
--------------------------------------------------------------------------------
1. Graceful Degradation / "Zero-Docker Demo Mode":
   - If HBase is down -> fallback transparently to reading `data/twosides.parquet`.
   - If Kafka is down -> fallback to reading existing alerts from SQLite / DuckDB.
   - BENEFIT: Allows anyone (evaluator, recruiter, professor) to run `python app.py`
     without needing Docker or 16 GB of free RAM.

2. Model Benchmark & Scientific Validation Dashboard:
   - A dedicated "Model Validation & Benchmarks" panel or modal in the UI showing:
     * GNN on TWOSIDES: AUC-ROC, PR-AUC, Sensitivity, Specificity
     * LSTM Temporal: Validation Loss, MAE across time steps
     * BioBERT Clinical NER: Entity F1-score, Precision, Recall
   - BENEFIT: Turns an "interesting prototype" into an unimpeachable, scientifically
     credible biomedical platform.

3. Live Stream Pipeline Telemetry Badge in UI:
   - Real-time status indicator in the top navbar:
     "🟢 Stream: Active (Broker: 9092 • 18 msgs/min • Consumer Lag: 0)"
   - BENEFIT: Visually proves to judges and users that the distributed streaming
     bus is live and authentic, not mocked or static.

4. Interactive Swagger / OpenAPI Documentation (Flasgger):
   - Add OpenAPI UI at `/api/docs` in Flask (requires only ~10 lines of code).
   - BENEFIT: Provides an instant, interactive API explorer for all 20+ endpoints.
